# EasyBusy Chats для Bitrix24 Box

Модуль `easybusychats` добавляет EasyBusy Chats в коробочный Bitrix24 и связывает чаты с контактами и сделками CRM. Клиенту передаётся только каталог модуля или готовый ZIP-пакет: отдельная установка frontend и настройка AWS не требуются.

## Возможности

- отдельный пункт **EasyBusy Chats** в левом меню;
- единая доверенная авторизация пользователей Bitrix24 Box через короткоживущий JWT;
- автоматическое создание EasyBusy-сессии без персональных ключей пользователей;
- зашифрованное хранение Client Secret только на сервере Bitrix24;
- создание и поиск контакта из чата;
- автоматический поиск и привязка контакта по актуальному телефону EasyBusy;
- повторный поиск по кнопке и безопасный выбор при нескольких совпадениях;
- привязка, открытие и отвязка контакта без удаления CRM-сущности;
- создание, поиск, привязка, открытие и отвязка сделок;
- связанные чаты в карточках контакта и сделки;
- открытие конкретного чата из CRM по deep link;
- проверка CRM-прав текущего пользователя;
- отдельная политика доступа на базе группы Bitrix24;
- управление доступом сотрудников из настроек модуля;
- интерфейс на русском, английском и украинском языках.

## Требования

- коробочный Bitrix24 с модулями `main`, `intranet` и `crm`;
- PHP 8.1 или новее;
- настроенный ключ шифрования Bitrix24 (`crypto_key`);
- HTTPS на рабочем портале для production-эксплуатации;
- доступ сервера Bitrix24 к EasyBusy API;
- доступ браузеров пользователей к размещённому EasyBusy frontend;
- права администратора для установки.

## Установка

Подробная пошаговая инструкция со скриншотами: [Установка и настройка EasyBusy Chats в Bitrix24 Box](docs/installation.md).

1. Распакуйте пакет. В архиве должен находиться один каталог `easybusychats`.
2. Скопируйте его в `<DOCUMENT_ROOT>/local/modules/easybusychats`. Не допускайте вложенности `easybusychats/easybusychats`.
3. Убедитесь, что PHP может читать файлы модуля. Рекомендуемые права: `755` для каталогов и `644` для файлов.
4. Войдите в Bitrix24 администратором.
5. Откройте **Настройки → Marketplace → Установленные решения** либо `/bitrix/admin/partner_modules.php?lang=ru`.
6. Найдите **EasyBusy Chats** (`easybusychats`) и нажмите **Установить**.
7. Откройте **EasyBusy Chats** в левом меню.
8. Откройте административные настройки модуля и укажите выданные EasyBusy `Client ID` и `Client Secret`.
9. На вкладке **Доступ** отметьте сотрудников, которым разрешено использовать EasyBusy Chats.
10. Откройте **EasyBusy Chats** в левом меню. Авторизация текущего пользователя выполнится автоматически по его email в Bitrix24.

Установщик регистрирует модуль, создаёт только собственные таблицы, копирует страницу `/easybusychats/`, создаёт группу `EasyBusy Chats: Пользователи` (`EASYBUSYCHATS_ACCESS`) и включает блок EasyBusy в карточках CRM. Администратор, выполняющий установку, автоматически получает доступ. Для остальных сотрудников доступ по умолчанию закрыт.

Client Secret задаётся один раз администратором и сохраняется в зашифрованном поле собственной таблицы модуля. Пользователи не вводят и не видят секреты интеграции.

## Обновление

1. Сделайте резервную копию каталога модуля и базы Bitrix24 штатными средствами.
2. Замените содержимое `/local/modules/easybusychats` новой версией.
3. Откройте любую страницу Bitrix24: модуль идемпотентно применит новую версию своей схемы.
4. Повторно скопируйте `install/public/easybusychats` в `<DOCUMENT_ROOT>/easybusychats`, если обновление выполнялось вручную без установщика.
5. Очистите кэш Bitrix24 и OPcache.

Токены и CRM-связи при обновлении не очищаются.

## Настройки модуля

Страница настроек доступна в административном разделе Bitrix24. Стандартная поставка уже содержит адреса, предоставленные EasyBusy.

Доступны:

- URL размещённого EasyBusy frontend;
- точный origin frontend для защищённого `postMessage`;
- базовый URL EasyBusy API;
- имя компании EasyBusy;
- Box `Client ID` и зашифрованный `Client Secret`;
- вкладка **Доступ** со списком сотрудников и переключателями доступа;
- язык по умолчанию;
- включение контактов и сделок;
- таймаут запросов;
- безопасный диагностический журнал.

Изменять URL frontend и API следует только по инструкции EasyBusy. Клиенту не требуется настраивать CloudFront, S3 или другую AWS-инфраструктуру.

## Box JWT-авторизация и безопасность

1. Локальная страница и D7-контроллер проверяют действующую сессию Bitrix24.
2. Модуль проверяет, что пользователь является администратором либо входит в группу `EASYBUSYCHATS_ACCESS`. Без этого страница возвращает `403`, пункт меню скрывается, CRM-блок не подключается и runtime-токен не создаётся.
3. Модуль получает Bitrix user ID и email текущего пользователя.
4. Сервер формирует JWT `HS256` сроком на 300 секунд только с обязательными claims `email` и `exp`.
5. Сам сервер Bitrix24 отправляет JWT методом `POST` в `/chats/v1/plugin/box-edition/auth`. JWT и Client Secret не передаются в CloudFront frontend.
6. EasyBusy возвращает ограниченный по времени токен и идентификатор компании; только нормализованный `accessToken` передаётся iframe после защищённого handshake с проверкой origin, source, версии протокола, request ID и session nonce.
7. Access token хранится только в памяти iframe, не добавляется в URL, HTML, bundle, `localStorage` или журнал. До истечения сессии iframe автоматически получает новую авторизацию через перезагрузку.

`Client Secret` доступен только серверному коду и хранится в `CryptoField`. Страница настроек доступна только администраторам Bitrix24. Для production Bitrix24 и EasyBusy API должны использовать HTTPS.

## Таблицы модуля

### `b_easybusychats_box_credential`

Единственная запись с `Client ID` и зашифрованным `Client Secret` установки.

Таблица `b_easybusychats_user_token` предыдущих версий больше не используется. При обновлении старые записи не удаляются автоматически, чтобы обновление оставалось обратимым; удалить их можно после подтверждения успешного перехода на Box JWT.

### `b_easybusychats_chat_contact`

Связь EasyBusy-чата с контактом Bitrix24. Уникальный ключ: сайт + EasyBusy company ID + chat ID. Mapping хранит EasyBusy chat ID, account ID, provider и внешний contact ID в отдельных полях; Bitrix contact ID не используется вместо EasyBusy chat ID. Поле `LINK_SOURCE` фиксирует источник связи: `manual`, `contact_created`, `phone_auto` или `phone_selected`.

### `b_easybusychats_chat_deal`

Связи чата со сделками. Уникальный ключ: сайт + EasyBusy company ID + chat ID + deal ID.

При отвязке удаляется только mapping. Контакт, сделка и сообщения EasyBusy не удаляются.

## CRM-сценарии

При открытии непривязанного чата модуль получает актуальный телефон клиента из EasyBusy API и выполняет серверный поиск в CRM. Сначала проверяется полное совпадение очищенного номера, затем максимально длинный общий хвост не короче 9 цифр. Предварительный отбор использует телефонный индекс Bitrix24, полного сканирования CRM нет.

Если после дедупликации найден один доступный контакт, он связывается автоматически. При нескольких совпадениях появляется действие **Найденные контакты**, где пользователь выбирает нужную запись. Если совпадений нет, доступны **Найти по телефону**, **Создать контакт** и **Связать с контактом** в зависимости от прав пользователя. Повторный поиск заново получает телефон из EasyBusy API.

Существующая связь никогда не заменяется автоматическим поиском. Параллельные запросы одного чата объединяются, а серверная блокировка и уникальный ключ mapping защищают от двойного клика и повторного bootstrap.

Перед ручным созданием контакта выполняется проверка дубликатов по телефону и email.

Для привязанного чата доступны открытие и отвязка контакта, просмотр сделок, создание и привязка сделки. В карточках контакта и сделки модуль показывает связанные чаты. Кнопка открытия ведёт на `/easybusychats/` и выбирает нужный чат.

Все CRM-команды выполняются сервером от имени текущего пользователя. Модуль повторно проверяет права чтения, создания и изменения сущностей.

При повторном открытии из карточки CRM deep link передаёт идентификаторы с явными именами: `easyBusyCompanyId`, `chatId`, `accountId`, `provider` и `externalContactId`. Сообщения загружаются только по документированному маршруту EasyBusy API:

```text
/chats/v1/{provider}/{companyId}/account/{accountId}/chat/{chatId}/messages
```

Если обязательный EasyBusy chat/account ID отсутствует, запрос не отправляется. Ответ `404` завершает состояние загрузки и показывает понятную ошибку с возможностью повторить открытие.

## Удаление

1. Откройте список установленных решений.
2. Выберите `easybusychats` и нажмите **Удалить**.
3. Опция удаления данных управляет удалением mapping-таблиц. Оставьте её выключенной, если связи нужны для повторной установки.

Таблицы credentials и старых персональных токенов удаляются всегда, чтобы после удаления модуля на сервере не оставались секреты. Контакты, сделки и сообщения EasyBusy не удаляются.
Созданная модулем группа `EASYBUSYCHATS_ACCESS` и персональные пункты меню также удаляются.

## Диагностика

### Модуль или пункт меню не появился

- проверьте путь `/local/modules/easybusychats/install/index.php`;
- убедитесь, что каталог называется `easybusychats`;
- проверьте права чтения файлов для PHP;
- откройте `/easybusychats/` напрямую, очистите кэш меню и повторно войдите.

### Box-авторизация отклонена

- проверьте `Client ID` и повторно сохраните `Client Secret` в административных настройках;
- проверьте наличие корректного email у пользователя Bitrix24;
- проверьте доступ сервера Bitrix24 к EasyBusy API и базовый URL API;
- убедитесь, что в Bitrix24 настроен серверный `crypto_key`;
- проверьте синхронизацию времени сервера: JWT действует только 300 секунд.

### Пользователь не видит пункт EasyBusy Chats

- откройте административные настройки модуля и вкладку **Доступ**;
- включите доступ напротив нужного сотрудника и сохраните настройки;
- убедитесь, что у сотрудника есть активная учётная запись и email, совпадающий с пользователем EasyBusy;
- после изменения обновите страницу Bitrix24: персональный пункт меню синхронизируется автоматически.

### В iframe пусто или остаётся загрузка

- сначала проверьте настройки Box-авторизации и email текущего пользователя;
- проверьте доступность URL frontend из браузера пользователя;
- проверьте точное совпадение origin, включая схему и порт;
- при reverse proxy передавайте корректные `Host`, `X-Forwarded-Host` и `X-Forwarded-Proto`;
- после замены файлов очистите кэш Bitrix24 и OPcache.

### D7-контроллер не найден

Проверьте наличие и права чтения `.settings.php`, `include.php` и `lib/Controller/Api.php`. На Linux важен регистр имени `Api.php`.

### Журнал

При включённой диагностике модуль пишет только технические коды операций в `<DOCUMENT_ROOT>/local/logs/easybusychats.log`. Токены, содержимое сообщений, телефоны и email туда не записываются.
